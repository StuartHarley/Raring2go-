# Database Foundation

FND-003 establishes PostgreSQL as the transactional source of truth with Drizzle for typed schema, migrations and seed scripts. Provider-specific database services must stay behind `DATABASE_URL`; the domain layer must not depend on a managed database vendor.

## Identity Model

`users.email` is globally unique. Raring2go will have parent, advertiser, franchise, HQ and Super Admin users, but they represent one human identity that can hold memberships and roles in multiple organisations. This avoids duplicated accounts for the same person and keeps future account recovery, audit attribution and cross-organisation delegation unambiguous.

If a future requirement needs shared inboxes or multiple people behind one advertiser login, that should be modelled as organisation membership or delegated access, not duplicate user rows with the same email.

## Tenancy And Scope

The default access model is:

- `organisations` own commercial/franchise context.
- `memberships` attach users to organisations.
- `territories` belong to franchise organisations where applicable.
- `user_role_assignments` scope a role to an organisation and optionally a territory.

`territory_access` exists only for exceptional access that differs from the normal organisation/territory relationship. Most future screens should use membership plus scoped role assignments.

## Foundation Tables

FND-003 creates only foundation tables:

- `organisations`
- `users`
- `territories`
- `memberships`
- `roles`
- `permissions`
- `role_permissions`
- `user_role_assignments`
- `territory_access`
- `delegations`
- `audit_events`

Future domain tables for advertiser, franchise, publishing, finance, audience, automation and AI remain out of scope.

## Audit Strategy

`audit_events` is append-only. `entity_type` and `entity_id` are durable references, not foreign keys, so historical audit records survive soft deletion or future archival of referenced rows.

## Conventions

- UUID primary keys are generated by PostgreSQL with `gen_random_uuid()`.
- Timestamps use `timestamptz` and are stored in UTC.
- Soft delete uses nullable `deleted_at` on admin-managed foundation records.
- Stable lookup values use text plus application/Drizzle typing for now; hard PostgreSQL enums should be introduced only when values are truly stable.
- Seeds are deterministic and idempotent.

## Local Setup

```bash
docker compose up -d db
pnpm install
pnpm db:generate
pnpm db:migrate
pnpm db:seed
```

The default local connection string is in `.env.example`.
